# บันทึกการประชุมทีม — ฟีเจอร์ Split Bill (หารบิล)

**โปรเจกต์:** PaySmart — Split Bill
**ครั้งที่:** Sprint Review #6 (สัปดาห์สุดท้ายก่อน Go-live)
**วันที่:** 10 มิถุนายน 2026 เวลา 10:00–11:15
**สถานที่:** ห้องประชุม Orion / Google Meet
**ผู้บันทึก:** ปิยะ (PM)

## ผู้เข้าร่วม
- ปิยะ ชวนชื่น — Product Manager (เจ้าของโปรเจกต์)
- นภา ศรีสุข — Engineering Lead
- ธีรพงษ์ จันทร์เพ็ญ — Backend Engineer
- มินตรา วงศ์ดี — Mobile Developer (iOS/Android)

- (ไม่เข้าร่วม) คุณวิชัย — VP Product *(จะเข้าประชุม stakeholder พรุ่งนี้)*

## วาระที่ 1 — สรุปผล Beta 3 สัปดาห์
- ปล่อย closed beta ให้ผู้ใช้ 2,400 คน เป็นเวลา 3 สัปดาห์ (19 พ.ค. – 8 มิ.ย.)
- มีผู้ใช้ฟีเจอร์ Split Bill อย่างน้อย 1 ครั้ง = 38% ของ beta users
- ยอดสร้างบิลหารรวม 5,820 ครั้ง, มูลค่ารวมที่หารผ่านระบบ 4.1 ล้านบาท
- NPS ของ beta = 52 (เกินเป้าที่ตั้งไว้ 45)
- เสียงตอบรับเด่น: "หารแล้วทวงเงินอัตโนมัติสะดวกมาก" / ขอให้ "หารแบบไม่เท่ากันได้"

## วาระที่ 2 — สถานะ Engineering
- งานพัฒนา core เสร็จ 100% — ครบทุก user story ใน scope รอบนี้
- ระบบแจ้งเตือนทวงเงินอัตโนมัติ (auto-reminder) ทดสอบผ่านแล้ว
- ค่าเฉลี่ย response time ของ API หารบิล = 1.8 วินาที (เป้า < 2.0s)
- **ติดปัญหา:** ฟีเจอร์ "หารแบบกำหนดเอง (custom split)" ยังมีบั๊กเรื่องการปัดเศษสตางค์ — ยอดรวมหลังหารไม่ตรงกับยอดบิลในบางเคส (ดูรายละเอียดในผล QA)

## วาระที่ 3 — ประเด็นที่ต้องตัดสินใจ
1. จะ Go-live แบบเต็ม หรือ ปล่อยแบบ phased rollout (เริ่ม 10% ของผู้ใช้)?
2. ฟีเจอร์ custom split — จะรวมใน launch แรก หรือเลื่อนเป็น fast-follow?
3. งบ marketing สำหรับเปิดตัว — ทีม growth ขอ 800,000 บาท

## ข้อสรุป / สิ่งที่ตกลงกัน
- ทีมเห็นพ้องเสนอ **phased rollout เริ่มที่ 10%** เพื่อคุม risk ช่วงแรก
- เสนอ **เลื่อน custom split เป็น fast-follow** (ภายใน 3 สัปดาห์หลัง launch) เพื่อไม่ให้บั๊กปัดเศษกระทบวันเปิดตัว
- ตั้งเป้า **Go-live วันที่ 1 กรกฎาคม 2026**
- ต้องได้รับอนุมัติจาก stakeholder เรื่องงบ + วันเปิดตัวในประชุมพรุ่งนี้
